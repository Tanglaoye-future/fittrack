# FitFlow Pro v2 — UX 准则（认知负荷宪法）

**文档版本**: 2.0  
**创建日期**: 2026-05-27  
**性质**: **强约束**。任何 PR 在合并前都必须通过本文档 §9 的 checklist。

---

## 0. 为什么这份文档存在

职业健美运动员在备赛期，每天要做超过 200 个微小决策：
"这餐 100g 还是 110g 鸡胸？"、"这组打 8 还是 9 个？"、"今天补不补 BCAA？"、"教练上周说的调整在哪条消息里？"

如果我们的产品在这 200 个决策之外，再让用户做 50 个"App 决策"——
"我该点哪个按钮？这个数据填到哪个表单？刚才那条记录在哪里？"——
那么不管功能多丰富，**用户会放弃**。

所以我们只有一条最高准则：

> **每一次产品决策，都问自己一个问题：这个改动，让运动员每天的总点击数和总思考数变多了，还是变少了？变多即砍。**

下面 7 条具体准则是这条最高准则的展开。

---

## 1. 七条认知负荷准则

### 准则 1 ——"昨天怎么做，今天就怎么做"（默认值即历史值）

所有重复性输入的默认值 = 用户上一次的相同输入。

- 训练：每组的 weight / reps / RIR 默认值 = 上次同动作同组号的值
- 饮食：每餐的食材组合默认值 = 同 meal_slot 的最近一次组合
- 补剂：每日补剂打卡默认全部勾选

**反面例子**：让用户从空表单开始填。一旦发现"用户在打开页面后 3 秒内的首个动作是"删除"或"清空""，就是这条准则失败的信号。

---

### 准则 2 —— 模板优先于自由输入

任何高频行为都必须有模板，自由输入只是 fallback。

- 训练计划：周一-胸+三头、周二-背+二头……一次性建好后日常只点"开始"
- 饮食：每个备赛阶段一套餐单模板，日常只点"今日按计划执行"
- 补剂套餐：早间套餐 / 训练前套餐 / 训练后套餐 / 睡前套餐 —— 按时段一键打卡

**评判**：如果一个高频功能没有模板，PR 拒收。

---

### 准则 3 —— 三秒打卡（Quick Log）

所有日常打卡动作在主页 ≤ 3 次点击、≤ 5 秒内完成。

**性能门槛**：

| 动作 | 点击数 | 时间中位数 |
|---|---|---|
| 完成一组训练 | ≤ 3 | ≤ 5 秒 |
| 完成一餐（按计划） | 1 | ≤ 3 秒 |
| 完成一餐（自由餐） | ≤ 5 | ≤ 15 秒 |
| 补剂套餐打卡 | 1 | ≤ 3 秒 |
| 记一笔消费 | ≤ 4 | ≤ 10 秒 |
| 提交周 check-in | — | ≤ 5 分钟 |

**测量**：每个 release 跑一次"打卡耗时基准测试"，不达标的功能直接 revert。

---

### 准则 4 —— 零数学

用户永远不需要心算。

- 不算 macros：输入克数，系统反算 kcal / P / C / F
- 不算总卡路里：餐次累加由系统做
- 不算训练吨位：Session Summary 自动出
- 不算成本：消费按品类自动汇总
- 不算备赛剩余周数：倒数自动算

**反面例子**：UI 上出现"请输入热量"这种让用户去查的字段。

---

### 准则 5 —— 主动提醒，而非被动查询

凡是有"时间属性"的任务，必须由系统在合适的时间主动推。

| 触发 | 推送内容 |
|---|---|
| 训练前 30 分钟 | "记得 pre-workout" + 补剂清单 |
| 训练中每组完成 | 自动启动组间休息倒计时 |
| 餐次时间到 | 当前餐内容 + 一键打卡按钮 |
| 当日蛋白缺口 > 20g | 睡前 21:00 提醒 |
| 周日 20:00 | "本周 check-in 已预填，点开提交" |
| 教练回复 check-in | 立即推送 |
| 备赛剩余 7 天 | Peak week 协议自动激活 |

**禁区**：不发与当前任务无关的推送（不发"今日推荐健身餐"、不发"健身知识小贴士"）。

---

### 准则 6 —— 批量胜过单条

让用户一次性规划、每天确认。

- 周日：一次建好下周训练 + 餐单 + 补剂 → 周一到周日每天只点"完成"
- 月初：一次建好本月预算 + 循环消费（健身房月卡、教练月费）→ 自动展开为日级记录
- 备赛启动：一次配好 16 周 PhaseConfig → 系统按周自动推进 macros / cardio

**反面例子**：让用户每天重新建模板。

---

### 准则 7 —— 离线优先 + 后同步

健身房常常没信号。所有写操作必须满足：

1. 本地立即生效（IndexedDB + 乐观 UI）
2. 携带 `client_op_id`（UUID）+ `client_ts`（毫秒）入待同步队列
3. 网络恢复后台同步，幂等保证不重复提交
4. 冲突解决：服务端字段级 Last-Write-Wins，关键字段（如 stage_date）走人工确认

**禁区**：任何"必须联网才能完成"的核心打卡动作（除登录）。

## 2. 反模式清单（看到立即说"不"）

| 反模式 | 触发原因 |
|---|---|
| 弹出"你确定吗？" | 用户不需要被反复确认；用 Undo 替代 |
| 长表单（> 7 个字段） | 拆分 + 模板 + 默认值 |
| 让用户选下拉框中超过 7 项 | 用搜索 + 最近使用 + 收藏 |
| 让用户输入精确时间 | 默认"现在"，仅支持 ±5 分钟微调 |
| 必填字段超过 3 个 | 砍 / 设默认值 / 设可选 |
| "数据导入向导" | 数据库内置常用数据，用户不导 |
| 模态嵌套模态 | 重新设计流程 |
| 红色禁止 / 警告样式 | 健美运动员每天看的指标已经够焦虑；只用中性色 + 数字 |
| 数字祝贺动画（"恭喜达成目标！"） | 严肃备赛者觉得幼稚；最多用细微的色彩变化 |
| "高级用户才知道的隐藏功能" | 全部曝光在二级菜单或可发现；不藏 |

## 3. 视觉与文字风格

### 视觉

- **黑底白字**（备赛运动员经常在低光健身房看）
- **数字超大**（重量、reps、macros 必须 ≥ 32px，单手训练间隔可读）
- **可单手操作**（所有主要按钮在屏幕下半部）
- **极简动画**（≤ 200ms 过渡，禁用炫技动画）
- **图标 + 文字双标签**（健身房戴耳机看的是图标，办公室看是文字）

### 文字

- **二字以内的动词**（"开始"、"完成"、"加组"、"换菜"）
- **不出现"建议"、"推荐"、"或许"**（专业用户要确定性，不要软语气）
- **数字优先于副词**（不说"很多"，说"3200 kcal"）
- **中英混排时英文用专业缩写**（"RIR 1"，不说"还剩 1 个可练"）

---

## 4. 数据隐私的认知负荷

PED 模块、收入数据、教练对话——用户不应该每次都担心"这数据会被谁看到"。

- 字段级权限在 UI 上有清晰图标（🔒 仅自己 / 🤝 含教练 / 🌐 公开）
- 默认值永远是"最严格"（默认仅自己可见）
- PED 模块单独 PIN 码进入
- 教练查看学员数据时，学员收到通知

---

## 5. 跨端一致性（PWA 同一套代码）

- 桌面 / 平板 / 手机 / 装到主屏 —— 同一套交互
- 仅在屏宽 < 480px 时折叠侧栏
- 仅在 hover 不可用时（触屏）改用长按出菜单

---

## 6. 教练端的特殊认知负荷

教练每周日要看 8–25 名学员的 check-in，这是认知负荷的**重灾区**。

- 学员看板：一屏看完所有学员的"红黄绿"健康状态
- 标准化模板回复："本周很好，按计划"、"卡路里加 100"、"有氧加 10 分钟"——一键发送
- 上次评注自动浮现（节省"我上次跟他说啥来着"的回忆成本）
- 批量操作：把 5 个学员同时调"下周加有氧"

## 7. 实施这些准则需要的工程能力

| 准则 | 需要的工程能力 |
|---|---|
| 默认值即历史值 | 写时记录 last_values 缓存到 user_preferences |
| 模板优先 | 所有高频实体都有 `template_id` 字段 |
| 三秒打卡 | 主页 Quick Action 区域专项设计 |
| 零数学 | 后端 service 层封装所有反算逻辑 |
| 主动提醒 | Push 服务 + 定时任务 + 用户时区 |
| 批量胜过单条 | 模板系统 + 周/月级 generate API |
| 离线优先 | Service Worker + IndexedDB + 同步队列 + 幂等键 |

详细字段定义见 `DATABASE_SCHEMA_v2.md`，详细接口见 `API_DESIGN_v2.md`。

## 8. 验收过程

每周 Demo Day 必做一次"**新用户单手健身房测试**"：

- 找一个完全没用过的人，发他链接，让他完成"记录一次完整训练 + 一餐 + 一次称重"
- 全程不能解释、不能引导
- 用秒表计时
- 失败 = 当周 Backlog 第一优先级

## 9. PR 验收 Checklist（合并前必须勾完）

每个 PR 描述里粘贴下面这段，逐条打勾：

```markdown
## UX 准则 Checklist
- [ ] 本 PR 没有引入新的"空表单"（已设默认值或来自模板）
- [ ] 本 PR 没有新增让用户做心算的字段
- [ ] 本 PR 的所有高频动作 ≤ 3 次点击完成
- [ ] 本 PR 没有新增"必填且无默认值"超过 3 个的表单
- [ ] 本 PR 的所有写操作支持离线（带 client_op_id + 本地优先）
- [ ] 本 PR 的所有提醒只在合适时间触发（不发与当前任务无关的通知）
- [ ] 本 PR 的文案符合 §3（二字动词、数字优先、无软语气）
- [ ] 本 PR 在 360×640 屏幕单手可操作
- [ ] 本 PR 没有新增"你确定吗？"弹窗（改用 Undo）
- [ ] 本 PR 在断网状态下打开仍可使用核心功能
```

任何一条没勾就不允许合并。Reviewer 有否决权。
